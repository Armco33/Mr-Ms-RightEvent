Build a demo web app called "Mr Ms Right Event" (code name: "Tinder for events") in Next.js (App Router) + TypeScript + Tailwind CSS. The repo is https://github.com/Armco33/Mr-Ms-RightEvent. If the repo already has code, extend it and keep its conventions. Otherwise scaffold from scratch. This is a DEMO, so favor reliability and polish over completeness. No auth and no database.

## Goal
A 3-screen flow:
1. Chat with our agent bot "Co-Parrot" 🦜 (/)
2. Tinder-style swipe deck of 10 events (/swipe)
3. Final list of liked events with an "It's a Match" popup (/results)

## Dependencies
framer-motion, cheerio. Use built-in fetch (no axios).

## Shared code
- lib/types.ts:
  Prefs = { city: string; distanceMiles: number; vibe: string; type: "tech"|"entrepreneurship"|"hobby"|"coffee"; price: "free"|"paid"; email: string }
  EventCard = { id: string; title: string; start: string; venue: string; city: string; image: string; url: string; organizer: string; free: boolean }
- lib/prefs.ts: export DEMO_PREFS = { city: "Taipei", distanceMiles: 50, vibe: "cheerful", type: "tech", price: "free", email: "hello-allo@gmail.com" }
- Pass state between screens with sessionStorage (keys: "prefs", "liked").

## Screen 1: Co-Parrot chat (app/page.tsx, client component)
- Mobile-first layout, max-w-md centered, full-height chat. Header: "🦜 Co-Parrot".
- On load, Co-Parrot posts these bot messages one after another with a short typing delay (~600ms):
  1. "Hi, I'm Co-Parrot 🦜 Here's what I'll use to find your events:"
  2. A summary of the preset filters, one per line:
     📍 City: Taipei / 📏 Distance: 50 miles / 😄 Vibe: cheerful / 🏷️ Type: tech (options: tech, entrepreneurship, hobby, coffee) / 💸 Price: free / 📧 Luma email: hello-allo@gmail.com
  3. "Chat with me to tweak anything, or type “confirm” to start."
- The user can type freely (input + Send button, Enter to send). User bubbles are pink and right-aligned. Bot bubbles are gray and left-aligned. Auto-scroll to the newest message.
- For any message other than "confirm" (case-insensitive, trimmed), Co-Parrot replies: "Noted! (Demo presets are locked.) Type “confirm” when ready."
- On "confirm", Co-Parrot replies exactly: "Got it, will discover some new events. 🦜✨". Save DEMO_PREFS to sessionStorage, then navigate to /swipe after 1.5s.

## Events API via scraping (app/api/events/route.ts)
Do NOT use the Luma API. Scrape the public website server-side (runtime "nodejs", dynamic "force-dynamic").
1. Fetch https://lu.ma/taipei (follow redirects; if it fails, try https://luma.com/taipei) with headers: User-Agent of a normal desktop Chrome, Accept-Language "en-US,en;q=0.9".
2. Parse the HTML with cheerio. First try the <script id="__NEXT_DATA__"> JSON and walk it recursively to find event objects (objects with fields like api_id/name/start_at/url/cover_url/geo_address_info or a nested "event" object). Fall back to <a href="/..."> cards plus og/meta tags if JSON is absent.
3. For each event, normalize to EventCard. Build url as https://lu.ma/<slug> if relative. Set city from geo_address_info.city, or default "Taipei" because this page is the Taipei feed. Use hosts[0].name for organizer, or "Organizer" if missing.
4. If fewer than 10 results, also fetch https://lu.ma/discover and the tech category page if it exists (try https://lu.ma/tech), merge, and dedupe by id/url.
5. Filter: city/venue matches /taipei|台北|臺北/i, AND free (no ticket price info, or text includes "Free"), AND prefer tech-related titles/descriptions (keywords: tech, AI, dev, startup, code, data, web3, hackathon, product, cloud). If tech matches are fewer than 10, fill the rest with other free Taipei events.
6. Return exactly 10 EventCards as JSON. Cache the result in memory for 10 minutes.
7. FALLBACK: if scraping fails or yields fewer than 10, fill from data/events.json (create it with 10 realistic free Taipei tech events: title, ISO start in the next 2 weeks, venue, city "Taipei", Unsplash image URL, url "https://lu.ma/taipei", organizer, free true). The demo must NEVER break because of scraping, so log a console warning and use the fallback.
8. Add a small badge in the /swipe UI only in development: "live" vs "fallback" (the API returns { source, events }).

## Screen 2: Swipe deck (app/swipe/page.tsx, client component)
- On mount, fetch /api/events. While loading, show "Co-Parrot is searching… 🦜" with a bouncing parrot.
- Show a progress indicator "n / 10" and a stack of cards. The top card is draggable horizontally (framer-motion drag="x"), rotates with the drag, and shows a green "GOING" label when dragged right and a red "NOPE" label when dragged left. A swipe past 120px counts. Animate the card flying off-screen.
- Card contents: cover image (top ~60%), title, formatted date/time (Asia/Taipei timezone), venue, organizer, and a green "Free" chip.
- Also provide ❌ and 💚 buttons below the deck that trigger the same swipe actions.
- RIGHT swipe: add the event to the liked list, then show a full-card reaction overlay for ~1.8s (buttons disabled meanwhile): a large pulsing animated ❤️, "Great! 🎉", "Connecting & registering with the event organizer…", and a "waiting…" line with animated dots. Then advance.
- LEFT swipe: advance immediately.
- After the 10th event, save the liked array to sessionStorage and navigate to /results. If nothing was liked, still go to /results and show an empty state: "No matches this time, try again" with a button back to /.

## Screen 3: Results (app/results/page.tsx, client component)

- ~800ms after load, show a full-screen modal popup over a dark backdrop: a huge animated heart (framer-motion scale pulse, infinite, ~text-9xl), the heading "It's a Match!", the line "Organizer approved: <title of the first liked event>", and a "See my list" button that closes it. Add a simple confetti or floating-hearts effect using framer-motion only, with no extra library.
